# 업무일지 PWA v8.3 출시 후보

그날 한 일을 아주 짧게 남겨 퇴근할 때 "오늘 뭐 했지?"를 막고, 나중에 업무보고·인사평가·연봉협상·과거 처리 방식 확인에 꺼내 쓰는 개인용 업무일지.

v8.3은 v8.2의 **업무 기록 단순화**를 유지하면서, 출시 전 재검증에서 발견된 동기화·복구·데이터 무결성 문제를 보강한 버전이다.

## v8.3 핵심 기록 방식

신규 기록은 종류를 고르지 않는다.

`업무명 → 필요하면 맥락 표시 → 저장`

- 신규 기록은 내부적으로 `cat=업무`로 저장
- 발생 경로: `기본 / 요청받음 / 내가 먼저 함`
- `문제해결`은 독립 체크(`solved`)로 기록
- 프로젝트·메모는 선택 입력
- `☆`를 눌러 인사평가 때 기억할 대표 업무 표시
- 기존 `수정 / 검수 / 진행관리 / 회의 / 해결 / 기타 / 요청` 기록은 변환하거나 삭제하지 않음
- 과거 기록 편집 시 기존 종류는 읽기 전용으로 표시
- 기존 `해결` 기록은 과거 데이터의 `solved`가 비어 있으면 문제해결 기록으로 계속 해석

## 요청받은 일

1. 업무명 입력
2. `요청받음` 선택
3. 요청자 입력
4. `지금 / 오늘 / 내일 / 날짜` 선택
5. 필요하면 `문제해결` 체크
6. 저장

- `지금`: 바로 현재 날짜의 업무 기록으로 저장
- `오늘 / 내일 / 날짜`: `해야 할 요청`에 대기
- 요청받은 시각은 저장 순간 자동 기록
- `시작`을 누르면 실제 처리 날짜·시각을 기록하고 업무 기록으로 이동
- 잘못 시작한 요청은 편집 화면에서 `해야 할 요청으로 되돌리기` 가능
- 대기 요청의 발생 경로를 `기본` 또는 `내가 먼저 함`으로 바꾸면 모순된 pending 상태를 남기지 않고 일반 기록으로 정리

## 월별 요약

- 대표 업무
- 전체 기록 수
- 요청받은 수
- 요청 처리 수
- 내가 먼저 한 수
- 아직 대기 중인 요청
- 내가 먼저 챙긴 일
- 해결한 문제
- 프로젝트별 기록 수
- 회고의 잘한 점 / 힘들었던 점

예전의 `수정·검수` 건수는 제거했다. 건수 자체를 성과 점수로 평가하기보다 당시 업무와 기여를 되살리는 용도다.

## v8.3 데이터 안전성 보강

### 로컬 저장

- 기록과 outbox를 하나의 저장 트랜잭션처럼 처리
- 저장 도중 실패하면 한쪽만 남지 않도록 롤백
- 저장 중 앱이 종료될 경우 `worklog_storage_journal`을 이용해 다음 실행에서 복구
- 깨진 localStorage JSON을 빈 데이터로 덮지 않고 `*.corrupt.<timestamp>` 키로 격리
- 잘못된 outbox 항목도 정상 항목과 분리해 보존
- localStorage 쓰기 실패 시 성공한 것처럼 표시하지 않음

### Google Sheets 동기화

Google Sheets가 원본(canonical)이고 localStorage는 캐시 + 오프라인 저장소다.

- 모든 쓰기는 **GET + query string**만 사용
- 오프라인 입력은 outbox에 저장 후 온라인 복귀 시 전송
- 전송 중 같은 기록을 다시 수정·삭제해도 새 요청을 잃지 않도록 qid 기준 처리
- 삭제는 실제 행 삭제가 아니라 `deleted=true` tombstone
- 오래된 서버 데이터가 아직 전송하지 않은 로컬 삭제를 되살리지 못하게 함
- `updatedAt`이 최신인 기록이 우선이며, 같으면 `deviceId`로 결정
- 충돌에서 밀린 버전은 7일 동안 로컬 recovery에 최대 100건 보존
- 서버 revision + `sinceRev`로 평상시 변경분만 가져오고, 필요하면 `전체 다시 맞추기` 가능
- 같은 브라우저의 여러 창이 동시에 outbox를 전송하지 않도록 sync lease 사용
- 다른 창의 기록 변경은 BroadcastChannel/storage 이벤트로 반영
- 15초 timeout + 일시적 네트워크/429/5xx 오류 재시도
- 서버 쓰기 실패 후 pull만 성공한 경우 전체 동기화 성공으로 표시하지 않음

### 잘못된 서버/시트 연결 방지

서버 응답에서 다음 값을 확인한다.

- `appId = dayeon-worklog`
- `schemaVersion = 3`
- `storeId = 연결된 Google Spreadsheet ID`

가계부 Apps Script 등 다른 웹 앱 URL을 잘못 입력하거나, 기존 연결과 다른 시트가 들어오면 데이터 병합 전에 차단한다.

### 서버 입력 검증

- 실제 존재하는 날짜만 허용
- 유효한 시간만 허용
- 비정상 `updatedAt`을 현재 시각으로 바꾸지 않고 거부
- 필드 길이와 상태값 검증
- 모르는 action은 성공 처리하지 않고 오류 반환
- Apps Script 쓰기에는 LockService 사용

## 기존 데이터 보존

기존 영문 `Log`와 한글 `로그`, 영문 `Reflection`과 한글 `회고`를 모두 읽는다. 과거 행을 자동 이동·삭제하지 않는다.

기존 로그의 앞 7개 컬럼 순서는 그대로 유지한다.

`id | date | time | cat | content | updatedAt | deleted`

필요한 메타데이터 컬럼은 오른쪽에 추가한다.

`origin | requester | requestedAt | dueDate | project | memo | highlight | status | actualStartedAt | solved | deviceId | rev`

`solved`는 하위 호환을 위해 3상태로 읽는다.

- 빈칸: 구버전 미지정
- `TRUE/Y`: 문제해결
- `FALSE/N`: 명시적으로 문제해결 아님

따라서 기존 `cat=해결` + `solved` 빈칸 기록도 계속 `해결한 문제`에 포함된다.

기존 핵심 localStorage 키도 그대로 유지한다.

- `worklog_logs`
- `worklog_reflections`
- `worklog_outbox`
- `worklog_gas_url`
- `worklog_gas_token`

v8.3의 안전 기능을 위해 device/store/revision/recovery 등의 보조 키가 추가된다.

## 백업과 복원

설정에서 다음 기능을 제공한다.

- JSON 백업 저장
- JSON 백업 병합 복원
- CSV 내보내기
- 전체 다시 맞추기

JSON 복원은 기존 기록을 무조건 덮지 않고 ID와 버전을 비교해 더 최신인 데이터만 병합한다. 적용 전에 추가/갱신/오류 건수를 보여준다. 웹 앱 URL과 토큰은 백업 파일에 포함하지 않는다.

## 업데이트 순서

### 0. Google Sheets 사본 백업

현재 업무일지 Google 스프레드시트에서 `파일 → 사본 만들기`로 한 번 백업한다.

### 1. Apps Script를 먼저 v8.3으로 교체

**중요: v8.3 프론트엔드보다 Code.gs를 먼저 배포한다.** 새 앱은 서버의 appId/schema/storeId를 검증하므로, 프론트만 먼저 올리면 구버전 서버를 의도적으로 거부한다.

1. 기존 업무일지 Google 스프레드시트 열기
2. `확장 프로그램 → Apps Script`
3. 기존 코드를 이 패키지의 `Code.gs` 전체 내용으로 교체
4. 맨 위 `TOKEN`을 **현재 사용 중인 토큰과 정확히 같은 값**으로 변경
5. 저장
6. `배포 → 배포 관리 → 기존 웹 앱 편집 → 버전: 새 버전 → 배포`
7. 기존 `/exec` URL은 그대로 유지
8. 실행 계정은 `나`, 접근 권한은 반드시 **모든 사용자** 유지

새 배포 URL을 만들 필요 없다.

### 2. GitHub Pages 파일 교체

저장소 루트에서 다음 파일을 교체한다.

- `index.html`
- `style.css`
- `app.js`
- `manifest.json`
- `sw.js`
- `screenshots/` 폴더

기존 `icons/` 폴더는 그대로 유지한다. 아이콘 파일은 이번 업데이트에서 변경하지 않았다.

서비스워커 캐시는 `worklog-cache-v8-3`으로 증가했다.

### 3. 실제 앱 확인

1. 기존 설치된 업무일지를 완전히 종료 후 다시 열기
2. 설정에서 `앱 v8.3.0` 표시 확인
3. `지금 동기화` 실행
4. 기존 히스토리 날짜와 기존 `해결` 기록 확인
5. 새 일반 업무 1건 저장 후 Google Sheets 확인
6. 새 `문제해결` 업무 1건 저장 후 Sheets의 `solved` 확인
7. Sheets에서 받은 데이터가 앱을 다시 열었을 때 유지되는지 확인
8. 비행기 모드에서 1건 저장 → 온라인 복귀 → 자동 전송 확인

변경이 안 보이면 앱을 완전히 종료했다 다시 연다. 그래도 안 바뀌면 Chrome의 해당 사이트 캐시를 지우고 다시 접속한다. Google Sheets 데이터는 브라우저 캐시 삭제와 별개다.

## PWA 파일

- `index.html`, `style.css`, `app.js`: 앱 본체
- `manifest.json`, `sw.js`: 설치/오프라인/업데이트
- `Code.gs`: 기존 Google 스프레드시트의 Apps Script에 교체
- `screenshots/today-390x844.png`: manifest용 실제 렌더링 스크린샷
- `v8.3_검증_결과.md`: 출시 후보 자동 검증 결과
- `README_아이콘_안내.txt`: 기존 아이콘 유지 안내

## 실제 환경에서 마지막으로 확인할 항목

자동 테스트와 브라우저 mock 테스트는 수행했지만, 이 작업 환경에서는 사용자의 실제 Google Apps Script 배포 URL과 실제 Galaxy 환경까지 직접 조작할 수 없다.

따라서 배포 직전에는 `v8.3_검증_결과.md`의 실환경 점검 항목을 한 번 확인한다.
