# 업무일지 PWA

그때그때 기록하고, 회의는 캘린더로 따로 보고, 과거 기록은 히스토리에서 검색하는 개인용 업무일지.

Google Sheets가 원본(canonical) 데이터, 휴대폰/PC의 localStorage는 캐시 + 오프라인 임시 저장소다.

## 구조
- `index.html`, `style.css`, `app.js`, `manifest.json`, `sw.js`, `icons/` — 프론트엔드 (GitHub Pages에 그대로 배포)
- `Code.gs` — 구글 시트 백엔드 (Apps Script)

## 배포 순서

### 1. 구글 시트 백엔드 만들기
1. 새 구글 스프레드시트 생성 (예: "업무일지 DB")
2. 확장 프로그램 → Apps Script
3. 기본 코드 삭제 후 `Code.gs` 내용 전체 붙여넣기
4. 맨 위 `TOKEN` 값을 아무도 모를 문자열로 바꾼다. (강력한 보안 비밀값일 필요는 없고, 공개된 웹앱 URL에 대한 무차별 접근을 막는 정도의 목적)
5. 배포 → 새 배포 → 유형: 웹 앱
   - 실행 계정: 나
   - 액세스 권한: **모든 사용자** ("나만"으로 하면 앱에서 보내는 요청이 로그인 화면에 막혀 동기화가 안 됨. URL 자체가 추측 불가능한 긴 값이라 이렇게 열어도 URL을 모르면 접근 불가)
6. 배포 후 나오는 웹 앱 URL 복사 (`https://script.google.com/macros/s/.../exec` 형태)
7. 최초 1회 권한 승인 화면이 뜨면 본인 계정으로 승인

이미 배포한 적이 있다면: 배포 → 배포 관리 → 편집(연필) → 버전: 새 버전 으로 다시 배포 (URL은 그대로 유지됨).

### 2. 백엔드 URL/토큰 연결
앱을 열고 하단 탭의 **설정**에서
- 1번에서 복사한 URL
- 4번에서 정한 토큰

을 각각 붙여넣고 저장. app.js를 직접 수정할 필요 없음 (기기별로 한 번씩 입력).

### 3. GitHub Pages 배포
가장 쉬운 방법 (터미널 불필요):
1. github.com에서 새 저장소 생성 (개인용이니 이름은 눈에 띄지 않게)
2. 저장소 페이지에서 "Add file → Upload files"로 이 폴더의 파일 전체를 드래그해서 업로드 (icons 폴더 포함)
3. Settings → Pages → Branch를 main(또는 master) / root로 설정 → Save
4. 몇 분 뒤 나오는 주소가 접속 주소

터미널을 쓴다면:
```
git remote add origin <저장소 URL>
git branch -M main
git push -u origin main
```

### 4. 휴대폰/PC에 설치
- 안드로이드 크롬: 접속 후 메뉴 → **"앱 설치"** (단순 "홈 화면에 추가"는 브라우저 주소창이 남는 바로가기가 될 수 있음. "앱 설치" 항목이 안 보이면 icons 폴더가 제대로 업로드됐는지 저장소에서 확인)
- PC 크롬: 주소창 오른쪽 설치 아이콘 클릭
- 이미 예전 방식으로 홈 화면에 추가해뒀다면 그 아이콘은 지우고 위 방법으로 다시 설치해야 주소창 없이 열림

### 업데이트 후에도 변경이 안 보일 때
서비스 워커가 이전 버전을 캐시해두기 때문. `sw.js`의 `CACHE_NAME` 값을 파일 바꿀 때마다 새 값으로 올려서 업로드하면 강제로 갱신됨 (이번 업데이트에서 v4 → v5로 이미 올려둠). 그래도 안 보이면 브라우저에서 사이트 데이터/캐시를 한 번 지우고 다시 열기.

## 데이터 구조
- 로그 항목(그때그때 기록): 날짜, 시간, 분류(업무/회의/요청받은 일/해결한 문제/기타), 내용
- 회고(하루 정리): 한 줄 요약, 어려웠던 점&이유, 잘한 점, 내일은
- 캘린더 뷰는 분류가 "회의"인 로그 항목을 날짜별로 모아서 보여줌. 캘린더에서 직접 회의만 빠르게 추가하는 것도 가능.

## 동기화 방식 (Google Sheets가 원본)

```
                 Google Sheets (원본)
                    ▲         ▼
                    │         │
             Google Apps Script
                    ▲         ▼
                    │         │
                   PWA  ──  localStorage(캐시/오프라인 버퍼)
```

- 모든 쓰기(추가/수정/삭제)는 **GET + query string**으로 처리한다 (`?action=...&token=...&payload=...`). POST는 Apps Script 내부 리다이렉트 과정에서 body가 사라지는 문제가 있어 쓰지 않는다.
- 입력은 즉시 로컬(휴대폰/PC)에 저장되고, 화면 우측 상단 점으로 동기화 상태 표시(초록: 완료, 노랑: 대기, 회색: 미설정, 빨강: 실패/토큰 오류)
- 오프라인 상태에서 입력한 내용은 outbox 큐에 쌓아뒀다가 온라인이 되면 자동 전송
- 서버로 보내지 않은 outbox 항목이 같은 로그/같은 날 회고에 대해 여러 번 쌓이면, 최종 상태 하나로 압축해서 보낸다 (예: 추가 후 두 번 수정 → 최종 내용으로 한 번만 전송)
- **다음 시점마다 서버(Google Sheets)에서 최신 데이터를 자동으로 가져와 로컬/화면을 갱신한다**: 앱 최초 실행, 온라인 복귀, 앱이 다시 포그라운드로 전환될 때(탭 전환 후 복귀 등)
- 같은 id의 로그/같은 날짜의 회고가 로컬과 서버 양쪽에 있으면 `updatedAt`이 더 큰(최신) 쪽이 승자가 된다. 서버(Code.gs)도 동일한 기준으로, 이미 더 최신인 데이터가 있으면 오래된 요청을 무시한다.
- 삭제는 실제 행 삭제가 아니라 **tombstone 방식**(`deleted=true` 표시)으로 처리한다. `getAll`은 삭제된 항목도 포함해서 반환하며, 다른 기기는 이를 보고 자기 로컬에서도 해당 항목을 제거한다. 화면에는 삭제된 항목이 표시되지 않는다.
- 서버 데이터가 비어 있다고 해서 로컬 데이터를 자동으로 지우지 않는다. (아직 서버에 못 올린 로컬 데이터를 보호)
- 로컬(휴대폰/PC)이 오프라인이거나 Apps Script 응답이 실패해도 앱 사용 자체는 막히지 않는다. 기존 로컬 캐시로 계속 사용 가능.
