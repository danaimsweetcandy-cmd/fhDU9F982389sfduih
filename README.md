# 업무일지 PWA v8.6.1

v8.5.0 원본에 즐겨찾기를 추가한 v8.6.0의 재검증 결과를 반영한 보완판이다.
APP_VERSION 8.6.1, 캐시 worklog-cache-v8-6-1, API schemaVersion 3.

## 보완 내용
1. 즐겨찾기 전송 대기를 worklog_favorites_outbox 별도 키에 저장한다. 내부 FAV namespace는 유지한다. 기존 공용 큐와 구버전이 격리한 공용 큐 백업에서 유효한 즐겨찾기 작업만 이전한다. 격리 백업은 삭제하지 않는다. 이전 저장 실패 때도 기존 즐겨찾기 작업을 보존한다.
2. 업무·회고와 즐겨찾기의 수신 진행값을 분리한다. 즐겨찾기 손상/서버 읽기 실패/저장 실패가 업무·회고 수신을 중단하지 않는다. 손상 항목은 별도 보관하며 다음 수신 때 즐겨찾기 전체를 다시 확인한다.
3. 삭제 취소는 전용 알림으로 5초 유지한다. 다른 일반 알림이 덮어쓰지 않는다. 연속 삭제는 각 항목을 취소할 수 있다. 다른 기기에서 그 뒤에 변경한 삭제를 취소로 덮어쓰지 않는다.
4. 같은 종류·같은 이름의 여러 ID는 입력과 설정에서 한 이름으로 표시한다. 중복 원본을 보존하며 설정의 중복 정리로 확인 후 정리한다. 동일 이름 그룹의 수정·삭제·순서 이동은 함께 처리한다.
5. 오프라인에서도 변경 직후 전송 대기 건수를 갱신한다. 입력 중인 연결 URL/토큰을 상태 갱신이나 자동 동기화로 덮어쓰지 않는다.

입력창 가까이 + 저장 버튼을 고정하고 이미 등록된 값은 등록됨으로 표시한다.
칩 선택은 입력값만 채우며 입력창에 강제 포커스를 주지 않는다. 기존에 키보드가 열려 있으면 자동으로 닫는 동작은 하지 않는다.
칩 갱신 시 가로 스크롤 위치와 버튼 포커스를 유지한다. 변경 없는 영역은 다시 생성하지 않는다.

## 즐겨찾기 사용
- 요청자는 80자, 프로젝트는 120자까지 허용한다.
- 이름 앞뒤 공백을 제거하며 빈 이름·같은 종류의 중복 직접 등록을 거부한다. 영문 대소문자는 구분한다.
- 새 이름 직접 등록은 종류별 고유 이름 50개까지다.
- 기기 간 동시 등록이나 백업 병합으로 50개를 넘은 기존 이름도 보존한다. 안내 후 새 등록을 제한하며 수정/삭제/순서 이동/삭제 취소는 계속 가능하다.
- 즐겨찾기 이름 수정·삭제는 업무 기록 속 이름을 바꾸지 않는다.
- 입력 화면과 수정 모달의 칩, 빠른 등록, 요청자/프로젝트 과거 기록 자동완성을 지원한다.
- JSON 백업은 즐겨찾기와 tombstone을 포함한다. 즐겨찾기가 없는 과거 백업도 병합한다. CSV는 v8.5 그대로다.
- 설정의 중복 정리는 중복 ID를 삭제 상태로 만들고 이름 하나를 유지한다. 기존 업무 데이터에는 영향이 없다.

## 서버와 저장
Favorites 시트 컬럼: id / kind / label / order / deleted / updatedAt / deviceId / rev.
서버 쓰기: UPSERT_FAVORITE / DELETE_FAVORITE, GET + query string.
즐겨찾기 저장: worklog_favorites.
즐겨찾기 전송 큐: worklog_favorites_outbox.
업무·회고 진행값: worklog_server_revision.
즐겨찾기 진행값: worklog_favorites_revision.
손상 항목 보관: worklog_favorites_invalid. 오류 발생 시 전체 재수신 플래그를 유지한다.
서버 getAll은 sinceRev 및 별도 sinceFavoriteRev를 지원한다. 이전 클라이언트가 sinceFavoriteRev를 생략하면 기존 sinceRev 기준으로 응답한다.
즐겨찾기 서버 읽기 실패는 favoritesError를 포함한 정상 업무·회고 응답으로 전달한다.
schemaVersion은 3이다. contextFlagsV1 / requestWorkflowV1 / favoritesV1 / favoritesSyncV2를 쓰기 전에 확인한다.
구형 백엔드가 새 수신 진행값을 무시하지 않도록 v8.6.1 Code.gs가 필요하다.

## 배포 순서
1. Google Sheet 사본과 기존 앱 JSON 백업을 보관한다.
2. Code.gs의 TOKEN을 현재 사용 중인 값으로 유지한 후 새 코드를 적용한다.
3. setup()을 실행한다. Favorites가 없으면 만들고 기존 Log/Reflection 행은 바꾸지 않는다.
4. 기존 Apps Script 배포를 새 버전으로 갱신한다. 접근 권한은 모든 사용자, 기존 /exec URL은 유지한다.
5. GitHub Pages에서 index.html / app.js / style.css / sw.js / manifest.json을 교체한다.
6. 기존 icons/와 screenshots/ 파일은 유지한다. 원본 v8.5 ZIP에 이미지가 없어서 이번 ZIP에도 포함하지 않았다.
7. 같은 앱의 기존 브라우저 탭과 PWA 창을 모두 닫고 다시 연다. 캐시 교체만으로 이미 열린 페이지의 실행 코드가 즉시 바뀌지는 않는다.
8. 설정의 앱 v8.6.1을 확인하고 연결 확인·전체 다시 맞추기를 실행한다.
9. 두 기기에서 즐겨찾기 추가/수정/순서 변경/삭제/취소를 왕복 확인한다. 비행기 모드에서 변경 후 온라인 복귀 전송도 확인한다.

원본 업무·요청 데이터 모델과 서버 기존 Log/Reflection 헤더, CSV 핵심 함수는 그대로 유지했다.
즐겨찾기 오류 표시가 계속 남으면 Favorites 시트의 kind/label/order/updatedAt 등 손상 값을 확인하고 수정 후 다시 동기화한다. 오류 행 원본은 로컬에 최대 최근 100개를 별도 보관한다.
