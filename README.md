# 업무일지 PWA v8.4 출시 후보

그날 한 일을 짧게 남겨 퇴근할 때 "오늘 뭐 했지?"를 막고, 나중에 업무보고·인사평가·연봉협상·과거 처리 방식 확인에 꺼내 쓰는 개인용 업무일지.

v8.4는 v8.3의 동기화·복구 안전장치를 그대로 유지하면서, 업무 종류를 다시 늘리지 않고 **회의 / 문제해결 / 협업·지원** 세 가지를 독립적인 맥락 태그로 추가한 버전이다.

## 기록 방식

신규 기록은 여전히 종류를 고르지 않는다.

`업무명 → 필요하면 맥락 태그/발생 경로 표시 → 저장`

- 신규 기록의 내부 분류는 계속 `cat=업무`
- 발생 경로: `기본 / 요청받음 / 내가 먼저 함`
- 독립 태그: `회의 / 문제해결 / 협업·지원`
- 세 태그는 서로 배타적이지 않아 한 업무에 여러 개를 동시에 체크 가능
- 프로젝트·메모는 선택 입력
- `☆`를 눌러 인사평가 때 기억할 대표 업무 표시
- 기존 `수정 / 검수 / 진행관리 / 회의 / 해결 / 기타 / 요청` 기록은 변환하거나 삭제하지 않음

### 독립 태그의 의미

- `회의`: 나중에 논의·결정 내용을 다시 찾기 위한 기록
- `문제해결`: 문제를 발견하거나 원인을 찾고 해결한 기여
- `협업·지원`: 동료·타팀·외주·신입 지원, 인수인계, 피드백 등 메인 산출물에서 놓치기 쉬운 기여

기존 `cat=회의` 기록에서 새 `meeting` 값이 비어 있으면 자동으로 회의로 해석한다. 기존 `cat=해결` 기록에서 `solved` 값이 비어 있으면 문제해결로 해석한다.

## 요청받은 일

1. 업무명 입력
2. `요청받음` 선택
3. 요청자 입력
4. `지금 / 오늘 / 내일 / 날짜` 선택
5. 필요하면 `회의 / 문제해결 / 협업·지원` 체크
6. 저장

- `지금`: 바로 현재 날짜 업무 기록으로 저장
- `오늘 / 내일 / 날짜`: `해야 할 요청`에 대기
- 요청받은 시각은 저장 순간 자동 기록
- `시작`을 누르면 실제 처리 날짜·시각을 기록하고 업무 기록으로 이동
- 편집 화면에서 `해야 할 요청으로 되돌리기` 가능
- 대기 요청의 발생 경로를 일반 업무로 바꾸면 모순된 pending 상태를 남기지 않고 정리

## 월별 요약

업무 흐름에서 다음 수치를 확인한다.

- 전체 기록
- 요청받음
- 요청 처리
- 내가 먼저 함
- 회의
- 문제해결
- 협업·지원
- 요청 중 대기

아래 목록도 따로 모아본다.

- 대표 업무
- 내가 먼저 챙긴 일
- 해결한 문제
- 협업·지원
- 회의 기록
- 프로젝트·회사 기여
- 회고의 잘한 점 / 힘들었던 점

예전의 `수정·검수` 건수는 다시 추가하지 않았다. 세 독립 태그는 직무 종류 분류가 아니라 나중에 회상·검색·평가할 가치가 큰 맥락만 남기는 용도다.

## 검색·편집·내보내기

- 히스토리에서 `회의`, `문제해결`, `협업`, `지원` 등의 태그명으로 검색 가능
- 편집 화면에서 세 태그를 각각 켜고 끌 수 있음
- CSV에 `회의 / 문제해결 / 협업·지원` 컬럼 포함
- JSON 백업/병합 복원에도 세 태그가 그대로 보존됨

## Google Sheets 컬럼과 하위 호환

기존 로그의 앞 19개 컬럼 순서는 그대로 유지하고, 신규 필드는 오른쪽 끝에 추가한다.

기존 필드:

`id | date | time | cat | content | updatedAt | deleted | origin | requester | requestedAt | dueDate | project | memo | highlight | status | actualStartedAt | solved | deviceId | rev`

v8.4 추가 필드:

`meeting | support`

`solved / meeting / support`는 서버에서 빈칸과 명시적 false를 구분할 수 있도록 3상태로 읽는다.

- 빈칸: 구버전에서 미지정
- `TRUE/Y`: 해당 태그 사용
- `FALSE/N`: 명시적으로 사용하지 않음

v8.4 백엔드는 API `schemaVersion=3`을 유지한다. 대신 응답에 `contextFlagsV1` capability를 추가한다.

- v8.4 프론트엔드는 **어떤 쓰기보다 먼저** 이 capability를 확인한다.
- 따라서 구형 v8.3 `Code.gs`에 새 태그를 모르고 저장하는 일을 막는다.
- v8.3 프론트엔드는 v8.4 백엔드의 추가 capability를 무시하므로 계속 동작한다.
- v8.3 클라이언트가 v8.4 기록을 수정해도 보내지 않은 `meeting/support` 값은 서버 partial merge로 보존한다.

## v8.3에서 유지되는 데이터 안전 장치

### 로컬 저장

- 기록과 outbox를 저장 journal로 묶어 반쪽 저장 방지
- 저장 실패 시 성공 UI를 표시하지 않고 롤백
- 비정상 localStorage JSON은 `*.corrupt.<timestamp>`로 격리
- 잘못된 outbox 항목을 정상 큐와 분리
- 저장 도중 앱이 종료돼도 다음 실행에서 journal 복구

### 동기화

- Google Sheets가 원본(canonical), localStorage는 캐시 + 오프라인 저장소
- 모든 쓰기는 **GET + query string**
- 오프라인 기록은 outbox 후 온라인 복귀 시 전송
- 전송 중 동일 기록 재수정·삭제 시 qid 기준으로 새 요청 보존
- 삭제는 `deleted=true` tombstone
- `updatedAt` 우선, 동일하면 `deviceId` tie-break
- 충돌 패배본 7일 recovery 보존
- revision + `sinceRev` 증분 pull, 필요 시 전체 재동기화
- 같은 브라우저 여러 창의 동시 flush를 sync lease로 방지
- 15초 timeout + 일시적인 네트워크/429/5xx 재시도
- write 실패 후 pull만 성공해도 전체 성공으로 오판하지 않음

### 서버 검증

- `appId / schemaVersion / storeId / capability` 검증
- 실제 존재하는 날짜와 유효한 시간만 허용
- 비정상 `updatedAt` 거부
- 필드 길이·상태값 검증
- 모르는 action 거부
- Apps Script 쓰기에 LockService 사용

## 백업과 복원

설정에서:

- JSON 백업 저장
- JSON 백업 병합 복원
- CSV 저장
- 전체 다시 맞추기

JSON 복원은 ID와 버전을 비교해 더 최신인 데이터만 병합한다. 웹 앱 URL과 토큰은 백업에 포함하지 않는다.

## 업데이트 순서

### 0. Google Sheets 사본 백업

현재 업무일지 스프레드시트에서 `파일 → 사본 만들기`로 한 번 백업한다.

### 1. Apps Script를 먼저 v8.4로 교체

**중요: `Code.gs`를 먼저 배포한 뒤 프론트엔드를 올린다.** v8.4 프론트는 새 태그 capability가 없는 서버에는 데이터를 쓰지 않는다.

1. 기존 업무일지 Google 스프레드시트 열기
2. `확장 프로그램 → Apps Script`
3. 기존 코드를 이 패키지의 `Code.gs` 전체 내용으로 교체
4. 맨 위 `TOKEN`을 현재 사용 중인 토큰과 정확히 같은 값으로 변경
5. 저장
6. `배포 → 배포 관리 → 기존 웹 앱 편집 → 버전: 새 버전 → 배포`
7. 기존 `/exec` URL은 그대로 유지
8. 실행 계정 `나`, 접근 권한 **모든 사용자** 유지

### 2. GitHub Pages 파일 교체

저장소 루트에서 다음 파일을 새 파일로 교체한다.

- `index.html`
- `style.css`
- `app.js`
- `manifest.json`
- `sw.js`
- `screenshots/` 폴더

기존 `icons/` 폴더는 그대로 유지한다. 서비스워커 캐시는 `worklog-cache-v8-4`로 증가했다.

### 3. 실제 앱 확인

1. 기존 설치된 업무일지를 완전히 종료 후 다시 열기
2. 설정에서 `앱 v8.4.0` 확인
3. `지금 동기화` 실행
4. 기존 `회의`와 `해결` 기록이 각각 새 태그로 보이는지 확인
5. `회의 / 문제해결 / 협업·지원`을 모두 체크한 테스트 기록 1건 저장
6. Google Sheets에 `meeting / solved / support`가 정상 저장되는지 확인
7. 다른 기기에서 동기화 후 세 태그가 동일하게 보이는지 확인
8. 비행기 모드 저장 → 온라인 복귀 → 자동 전송 확인
