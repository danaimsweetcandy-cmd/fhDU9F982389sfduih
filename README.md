# 업무일지 PWA v8.1

업무 진행상황과 요청받은 일, 메인 업무 밖의 기여를 부담 없이 기록하고, 인사평가·연봉협상 때 사실 근거로 꺼내보며, 월별 업무 흐름과 회고로 번아웃·성장을 확인하는 개인용 업무일지.

## v8 핵심 기능

- 평소 입력은 `업무명 → 종류 → 저장` 수준 유지
- 발생 경로를 `기본 / 요청받음 / 내가 먼저 함`으로 별도 기록
- `요청받음`일 때만 요청자와 `지금 / 오늘 / 내일 / 날짜`가 나타남
- `오늘/내일/날짜` 요청은 받은 순간 바로 저장되고 `해야 할 요청`에 남음
- 요청받은 시각은 자동 저장, 실제 처리할 때 `시작`을 누르면 실제 처리 날짜·시각이 따로 기록됨
- 종료시간 기록 없음
- `☆` 한 번으로 인사평가 때 기억할 대표 업무 표시
- 월별 요약에서 대표 업무, 요청 처리, 내가 먼저 한 일, 수정·검수, 해결한 문제, 프로젝트, 회고를 한 번에 확인
- 기존 일일 회고 데이터 유지
- 기존 히스토리와 기존 Google Sheets를 그대로 이어서 사용


## v8.1 릴리즈 안정화

- 전송 중 같은 기록을 다시 수정·삭제해도 남은 outbox를 자동으로 한 번 더 전송
- 회고는 입력 즉시 localStorage와 outbox에 함께 저장하고 네트워크 전송만 debounce
- 요청 대기 버튼을 `처리`에서 `시작`으로 명확화하고 대기로 되돌리기 추가
- 날짜·시작 시각 수정 시 `actualStartedAt`도 동일하게 갱신
- 구버전 앱이 기존 행을 수정해도 v8+ 신규 메타데이터가 빈 값으로 덮이지 않도록 서버 partial merge
- 월별 요약에서 `요청받음`과 `요청 처리`를 분리
- 처리된 요청에도 요청 시각·원래 예정일 표시
- 신규 기록에서는 예전 `요청` 카테고리를 숨기고, 기존 `요청` 기록 편집 때만 유지
- 화면 확대 허용, 폼 라벨·토글 상태·동기화 상태·토스트 접근성 보강
- 수정 모달의 포커스 이동, Tab 가두기, Esc 닫기, 닫은 뒤 원래 위치 복귀
- 작은 터치 영역과 저대비 텍스트·입력 경계 개선
- 회고 입력 길이와 GET URL 길이 방어 추가
- localStorage 저장 실패 시 성공한 것처럼 진행하지 않도록 방어
- 하단 탭 safe-area와 481~539px 폭 정렬 보정

## 기존 데이터 보존 방식

기존 `Log` 시트의 앞 7개 컬럼은 그대로 유지한다.

`id | date | time | cat | content | updatedAt | deleted`

v8.1은 그 오른쪽에 없는 컬럼만 자동 추가한다.

`origin | requester | requestedAt | dueDate | project | memo | highlight | status | actualStartedAt`

기존 행의 새 컬럼은 빈칸으로 남는다. 과거 기록을 새 분류로 추측 변환하지 않는다. 예전 `요청받은 일` 기록도 기존 의미 그대로 히스토리에서 볼 수 있다.

localStorage 키도 기존과 동일하게 유지한다.

- `worklog_logs`
- `worklog_reflections`
- `worklog_outbox`
- `worklog_gas_url`
- `worklog_gas_token`

따라서 같은 GitHub Pages 주소에서 업데이트하면 기존 기기 캐시와 시트 데이터가 이어진다.

## 업데이트 순서

### 0. 먼저 백업

기존 Google 스프레드시트에서 `파일 → 사본 만들기`로 한 번 백업해두는 것을 권장한다.

### 1. Apps Script 교체

1. 지금 쓰는 기존 업무일지 Google 스프레드시트를 연다.
2. `확장 프로그램 → Apps Script`를 연다.
3. 기존 코드를 `Code.gs` 전체 내용으로 교체한다.
4. **Code.gs 맨 위 TOKEN을 현재 사용 중인 토큰과 똑같이 넣는다.** 토큰을 바꾸면 앱의 기존 설정과 연결되지 않는다.
5. 저장한다.
6. `배포 → 배포 관리 → 기존 웹 앱의 편집(연필) → 버전: 새 버전 → 배포`한다.
7. 새 배포를 만들 필요 없다. 기존 `/exec` URL을 그대로 유지하면 앱 설정도 그대로 쓸 수 있다.
8. 웹 앱 접근 권한은 반드시 **모든 사용자**로 유지한다.

앱이 처음 `getAll`을 호출하면 기존 행을 건드리지 않고 필요한 새 컬럼만 오른쪽에 추가한다.

### 2. GitHub Pages 파일 교체

저장소 루트에서 다음 파일을 새 파일로 교체한다.

- `index.html`
- `style.css`
- `app.js`
- `manifest.json`
- `sw.js`

`icons/` 폴더는 기존 것을 그대로 유지한다.

`sw.js` 캐시는 이번 버전에서 `worklog-cache-v8-1`로 올려두었다.

### 3. 앱 확인

1. 기존 설치된 업무일지를 연다.
2. 잠시 후 새 화면이 보이는지 확인한다.
3. 안 바뀌면 앱을 완전히 종료했다 다시 연다.
4. 그래도 안 바뀌면 Chrome의 해당 사이트 캐시를 지우고 다시 접속한다. Google Sheets 데이터는 지워지지 않는다.
5. 설정 화면의 `지금 동기화`를 눌러 연결을 확인한다.
6. 히스토리에서 기존 기록이 그대로 보이는지 확인한다.

## 새 기록 방식

### 일반 업무

`업무명 → 종류 → 저장`

기본 발생 경로는 `기본`이다. 프로젝트나 메모는 필요한 경우에만 `추가 정보`에서 적는다.

### 요청받은 일

1. 종류 선택: 예) 검수
2. `요청받음`
3. 요청자 입력
4. `지금 / 오늘 / 내일 / 날짜` 선택
5. 저장

- `지금`: 바로 오늘 기록으로 저장
- `오늘 / 내일 / 날짜`: `해야 할 요청`에 대기
- 요청 시각은 저장 순간 자동 기록
- `시작`을 누르면 그 순간의 날짜와 시간이 실제 처리 시작으로 기록되고 오늘 기록으로 이동
- 실수로 시작한 요청은 기록 수정에서 `해야 할 요청으로 되돌리기`로 복구 가능
- 종료시간은 기록하지 않음

### 내가 먼저 한 일

`내가 먼저 함`을 선택해서 저장한다. 진행관리, 문제 사전 발견, 다른 작업자 지원처럼 평가 때 놓치기 쉬운 기여를 따로 확인할 수 있다.

### 대표 업무

기록 오른쪽의 `☆`를 누르면 `★`로 바뀌고 월별 요약의 `대표 업무`에 뜬다.

## 월별 요약

- 대표 업무
- 전체 기록 수
- 해당 월에 요청받은 수
- 해당 월에 실제 시작한 요청 수
- 내가 먼저 한 수
- 수정·검수 수
- 아직 대기 중인 요청
- 내가 먼저 챙긴 일
- 해결한 문제
- 프로젝트별 기록 수
- 회고의 잘한 점 / 힘들었던 점

건수 자체를 성과 점수처럼 평가하기 위한 화면이 아니라, 당시 업무량과 기여를 기억하기 위한 요약이다.

## 동기화

Google Sheets가 원본(canonical), localStorage는 캐시 + 오프라인 저장소다.

- 모든 쓰기는 GET + query string
- 오프라인 입력은 outbox에 저장 후 온라인 복귀 시 전송
- 같은 로그는 `updatedAt`이 최신인 쪽이 승리
- 삭제는 실제 행 삭제가 아니라 `deleted=true` tombstone
- 서버의 삭제 정보를 다른 기기도 받아 로컬에서 제거
- 서버가 비어 있다는 이유만으로 로컬 전용 데이터를 지우지 않음
- 전송 중 같은 로그를 다시 수정해도 새 outbox 항목을 잃지 않도록 qid 기준으로 처리
- 앱 실행, 온라인 복귀, 포그라운드 복귀, 동기화 버튼에서 서버 최신 상태 확인
