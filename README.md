# 업무일지 PWA v8.5.0

그날 한 일을 짧게 남기고, 여러 날 이어지는 요청 업무도 요청 원본과 날짜별 작업 기록을 분리해 보존하는 개인용 업무일지.

## v8.5 핵심 변경

v8.4의 동기화·복구 안전장치와 `회의 / 문제해결 / 협업·지원` 독립 태그를 그대로 유지하면서, 요청받은 업무를 여러 날에 걸쳐 처리할 수 있게 요청 흐름을 확장했다.

### 요청 업무 상태

새 요청 원본은 다음 상태 중 하나를 가진다.

- `waiting`: 아직 시작하지 않은 요청
- `in_progress`: 시작해서 진행 중인 요청
- `done`: 완료한 요청

화면에서는 `대기 / 진행중`으로 표시한다. 완료된 원본은 오늘 화면의 요청 목록에서 빠지고 월요약의 `완료한 요청`에 반영된다.

### 요청 원본과 날짜별 작업 기록 분리

요청 원본은 요청자, 요청받은 시각, 예정일, 프로젝트, 태그와 현재 상태를 보관한다.

실제로 일한 날에는 별도 작업 기록을 만든다. 작업 기록에는 원본 요청의 `id`가 `requestId`로 연결된다.

예시:

- 10/2 요청 원본: 상세페이지 리뉴얼, 진행중
- 10/2 작업 기록: 상세페이지 리뉴얼
- 10/3 작업 기록: 상세페이지 리뉴얼
- 10/4 작업 기록: 상세페이지 리뉴얼
- 10/4 요청 원본: 완료

따라서 이전 날짜의 작업 기록을 다음 날로 옮기지 않는다.

## 요청받은 일 입력

1. 업무명 입력
2. `요청받음` 선택
3. 요청자 입력
4. `지금 / 오늘 / 내일 / 날짜` 선택
5. 필요하면 `회의 / 문제해결 / 협업·지원` 체크
6. 필요하면 프로젝트·메모 입력
7. 저장

동작:

- `지금`: 요청 원본을 `진행중`으로 만들고 오늘 작업 기록도 함께 생성
- `오늘 / 내일 / 날짜`: 요청 원본을 `대기`로 저장
- 요청받은 시각은 저장 순간 자동 기록

## 요청 업무 카드

오늘 화면의 `요청 업무` 영역은 `진행 중`과 `대기`로 나뉜다.

### 대기 요청

- `시작`: 원본을 `진행중`으로 바꾸고 오늘 작업 기록 생성
- `+1일`: 예정일 하루 연기
- `수정`: 요청 내용 편집

### 진행 중 요청

- `오늘 기록`: 오늘 날짜의 작업 기록 생성
- 이미 오늘 기록이 있으면 `오늘 기록됨`으로 표시하고 중복 생성 차단
- `완료`: 원본을 완료 처리
- 완료하는 날의 작업 기록이 아직 없으면 자동으로 오늘 작업 기록도 생성
- `수정`: 요청 내용 편집

같은 요청의 하루 작업 기록 ID는 요청 원본과 날짜를 기반으로 결정해 여러 기기에서 같은 날 동시에 기록해도 같은 레코드로 합쳐질 수 있게 했다.

## 일반 업무 기록

요청 업무가 아닌 기존 방식은 그대로다.

`업무명 → 발생 경로/맥락 태그 → 저장`

- 신규 일반 기록의 내부 분류는 `cat=업무`
- 발생 경로: `기본 / 요청받음 / 내가 먼저 함`
- 독립 태그: `회의 / 문제해결 / 협업·지원`
- 프로젝트·메모 선택 입력
- `☆` 대표 업무 표시

## 기존 데이터 호환

기존 데이터를 자동으로 억지 변환하지 않는다.

- 기존 `origin=request + status=pending` 기록은 v8.5에서 `waiting` 요청 원본으로 해석
- 이 요청에서 `시작`을 누르는 순간 v8.5 요청 흐름으로 자연스럽게 이어짐
- 기존에 이미 `logged` 상태인 요청 기록은 과거의 1일 업무 기록으로 그대로 유지
- 기존 `cat=회의` + `meeting` 미지정은 회의로 해석
- 기존 `cat=해결` + `solved` 미지정은 문제해결로 해석

## 월별 요약

업무 흐름:

- 전체 작업 기록
- 요청받은 업무
- 완료한 요청
- 진행 중 요청
- 내가 먼저 함
- 회의
- 문제해결
- 협업·지원

`요청받은 업무`는 요청 원본을 기준으로 세므로 3일 동안 작업한 요청도 1건이다. 반면 `전체 작업 기록`에는 실제로 기록한 각 날짜의 작업이 모두 포함된다.

별도 목록:

- 대표 업무
- 완료한 요청
- 내가 먼저 챙긴 일
- 해결한 문제
- 협업·지원
- 회의 기록
- 프로젝트·회사 기여
- 회고의 잘한 점 / 힘들었던 점

## Google Sheets 컬럼

기존 컬럼 순서는 그대로 두고 오른쪽 끝에 새 필드를 추가한다.

기존 v8.4 끝부분:

`... rev | meeting | support`

v8.5 추가:

`requestId | requestState | completedAt`

의미:

- `requestId`: 날짜별 작업 기록이 연결된 요청 원본 ID. 요청 원본 자체는 빈칸
- `requestState`: 요청 원본 상태. `waiting / in_progress / done`; 일반 기록과 작업 기록은 빈칸
- `completedAt`: 요청 완료 시각

`solved / meeting / support`의 3상태 읽기와 기존 앞쪽 컬럼은 그대로 유지한다.

## 서버 호환성 보호

백엔드 API `schemaVersion=3`은 유지하고 capability에 다음을 제공한다.

- `contextFlagsV1`
- `requestWorkflowV1`

v8.5 프론트는 어떤 쓰기보다 먼저 두 capability를 모두 확인한다. 따라서 구형 v8.4 `Code.gs`에 새 요청 연결 필드를 모르고 저장하는 일을 막는다.

구형 v8.4 클라이언트가 v8.5 백엔드 기록을 수정하더라도 보내지 않은 `requestId / requestState / completedAt` 값은 서버 partial merge로 보존된다.

## 데이터 및 동기화 원칙

- Google Sheets가 원본(canonical), localStorage는 캐시 + 오프라인 저장소
- 모든 쓰기는 **GET + query string**. POST로 바꾸지 않는다.
- 기록과 outbox를 journal로 함께 저장해 반쪽 저장 방지
- 요청 `시작 / 오늘 기록 / 완료`처럼 여러 레코드를 동시에 바꾸는 동작도 logs + outbox를 한 journal에 저장
- 오프라인 기록은 outbox 후 온라인 복귀 시 전송
- 삭제는 `deleted=true` tombstone
- `updatedAt + deviceId`로 충돌 판정
- 충돌 패배본 7일 recovery 보존
- revision + `sinceRev` 증분 pull
- sync lease / BroadcastChannel로 같은 브라우저 여러 창 동시 flush 완화
- 15초 timeout + 일시적인 네트워크/429/5xx 재시도
- write 실패 후 pull만 성공해도 전체 성공으로 표시하지 않음

## 업데이트 순서

### 0. Google Sheets 사본 백업

현재 업무일지 스프레드시트에서 `파일 → 사본 만들기`로 백업한다.

### 1. Apps Script를 먼저 v8.5로 교체

**반드시 `Code.gs`를 먼저 배포한 뒤 프론트엔드를 올린다.**

1. 업무일지 Google 스프레드시트 열기
2. `확장 프로그램 → Apps Script`
3. 기존 코드를 새 `Code.gs` 전체 내용으로 교체
4. 맨 위 `TOKEN`을 현재 사용 중인 토큰과 동일하게 변경
5. 저장
6. `배포 → 배포 관리 → 기존 웹 앱 편집 → 버전: 새 버전 → 배포`
7. 기존 `/exec` URL 유지
8. 실행 계정 `나`
9. 접근 권한 **모든 사용자** 유지

### 2. GitHub Pages 파일 교체

저장소 루트에서 다음 파일을 교체한다.

- `index.html`
- `style.css`
- `app.js`
- `manifest.json`
- `sw.js`

기존 `icons/` 폴더는 그대로 유지한다.

새 스크린샷 파일이 패키지에 있으면 `screenshots/today-390x844.png`도 교체한다.

서비스워커 캐시는 `worklog-cache-v8-5`다.

### 3. 실제 앱 확인

1. 기존 설치된 업무일지 완전히 종료 후 다시 열기
2. 설정에서 `앱 v8.5.0` 확인
3. `지금 동기화`
4. 대기 요청 하나 생성
5. `시작`을 눌러 진행중 요청 + 오늘 작업 기록이 동시에 생기는지 확인
6. 같은 날 `오늘 기록됨`으로 중복이 막히는지 확인
7. 다음 날 또는 테스트용 날짜 변경 후 같은 요청 작업 기록을 별도로 남길 수 있는지 확인
8. `완료` 후 요청 카드에서 빠지고 월요약 `완료한 요청`에 반영되는지 확인
9. Google Sheets 오른쪽 끝에 `requestId / requestState / completedAt` 확인
10. 다른 기기에서 전체 동기화 후 같은 요청 연결이 유지되는지 확인
11. 비행기 모드 기록 → 온라인 복귀 자동 전송 확인
