# 업무일지 PWA v8.8.0

기준 파일: 사용자가 제공한 `worklog_v8.7.2_final.zip`.
목적: 인사평가에 자신의 기여를 설명하고, 업무 부담을 돌아보되 기록 자체가 부담이 되지 않게 한다.

## 배포 전 필수 확인

이번 버전은 **Code.gs 전체 교체와 기존 Apps Script 배포 갱신이 필요하다.** 단순 APP_ID 한 줄 변경으로 끝나지 않는다. `배포_먼저읽기.txt`의 순서에 따른다.

- ZIP의 TOKEN은 예시다. **기존 운영 토큰을 반드시 유지**한다. 예시 토큰으로는 요청을 거부하도록 변경했다.
- 기존 배포의 `/exec` 주소, 실행 계정 `나`, 접근 권한 `모든 사용자`를 유지한다.
- `setup()` 재실행, 시트 초기화, 기존 로컬 저장소 삭제는 필요 없다.
- 프론트엔드는 `index.html`, `app.js`, `style.css`, `sw.js`, `manifest.json` 전체를 교체한다.
- 기존 `icons/`, `screenshots/`는 유지한다. 원본 ZIP에도 없어 이번 패키지에 새로 넣지 않았다.
- 여러 기기와 기존 탭/PWA를 모두 같은 버전으로 업데이트한다. 이전 버전의 창을 함께 실행하면 새 저장 잠금이 그 창에는 적용되지 않는다.

## 편의성과 개인 정보

평소에는 업무명 입력과 저장만으로 충분하다. 결과·영향·증거 링크·평가용 한 줄 입력칸은 추가하지 않았다.

- 상단에 기기 저장/전송 대기/동기화 완료를 문장으로 표시한다. 오프라인은 정상 사용 상태다.
- 단건 작성본과 수정 작성본을 기기에 보관한다. 재실행 시 단건은 복원하고, 수정은 `작성 중이던 수정 이어쓰기`로 연다. 작성본 복원 기간은 7일이다. 작성 중 다른 기기에서 수정한 기록을 저장할 때는 충돌을 알려 준다.
- 일반 업무 삭제 후 10초 동안 실행 취소를 제공한다. 그 뒤 다른 기기에서 변경한 삭제를 강제로 덮어쓰지 않는다. 요청 원본을 삭제해도 이미 남긴 날짜별 작업 기록은 유지한다.
- 미래의 대기 요청은 `나중에 볼 요청`에 접어 둔다. 지난 예정일은 `일정 다시 보기`로 표시한다. 예정일을 실제 마감일로 간주하지 않는다.
- 회고는 선택이다. 한 항목만 적어도 된다. 연속 작성 점수, 미작성 경고, 자동 독촉은 없다.
- 월요약의 `평가용 기록 복사`는 기본적으로 대표 업무를 정리한다. 필요한 경우 `이번 달 전체 작업 포함`을 선택할 수 있다. 같은 요청에 이어진 작업은 묶고 업무명·날짜·요청자·프로젝트·태그·메모만 사용한다. **summary/difficulty/achievement/tomorrow 등 개인 회고는 전부 제외**한다. 성과를 추정하거나 AI로 내용을 추가하지 않는다. 클립보드 사용이 불가능하면 텍스트 파일로 저장한다.
- 설정의 `복구본 확인`에서 변경 전 내용과 충돌 복구본을 살펴보고 새 수정으로 복원할 수 있다. 최근 7일, 최대 100개이며 빠르게 연속 입력한 같은 기기의 회고는 묶어 보관한다. 복구자료 JSON에는 손상 원본도 별도 포함한다. 복구자료 내보내기는 원본 점검용이며 일반 백업 불러오기는 logs/reflections를 포함한 업무일지 JSON을 사용한다.

## 저장·동기화 보완

- 모든 서버 쓰기는 계속 GET + 쿼리스트링이다. localStorage 우선 저장과 오프라인 큐를 유지한다.
- 서버에 ADD가 저장된 뒤 응답만 끊겨도 후속 DELETE를 버리지 않는다. 없는 ID의 삭제도 서버에 tombstone으로 남겨 지연된 ADD가 되살리지 못하게 한다.
- 레코드·전송 큐를 변경할 때 Web Locks로 여러 창의 쓰기를 직렬화한다. 미지원 브라우저는 IndexedDB 읽기/쓰기 트랜잭션을 잠금으로 사용한다. 네트워크를 기다리는 동안에는 데이터 잠금을 잡지 않는다.
- 전송 완료 응답은 해당 qid만 제거한다. 기다리는 중 발생한 새 수정/삭제/실행 취소는 유지한다.
- 잘못된 서버 업무/회고는 따로 보관하고 업무·회고 진행값을 넘기지 않는다. 다음 수신은 전체 확인으로 재시도하므로 시트에서 행을 바로잡았을 때 같은 revision이어도 재수신할 수 있다. 정상 항목과 즐겨찾기는 독립적으로 보존한다.
- 시트 직접 변경은 일반 증분 동기화로 자동 탐지할 수 없다. 직접 수정한 뒤에는 앱의 `전체 다시 맞추기`를 실행한다.
- 서버 읽기도 쓰기와 같은 잠금을 사용한다. 시트 저장이 중간에 실패하면 미완료 표시를 남기고, 같은 요청 재전송 시 저장을 마무리한다. 이때는 미전송 큐가 있는 기기에서 다시 동기화해야 한다.
- 동기화 실패는 큐가 비었다는 이유로 성공 표시로 바뀌지 않는다. 입력 중에는 수신 데이터로 작성 중인 글·한글 조합·커서를 다시 그리지 않는다.
- 단건·일괄·수정은 GET 전송 길이를 저장 전에 점검한다. 한도를 넘으면 원문 작성본을 유지하고 짧게 정리한 뒤 저장하도록 안내한다. 회고는 자동 저장 특성상 원문과 큐를 먼저 보존하고 전송 길이 오류를 표시한다. 내용을 줄이면 같은 회고 큐 항목이 갱신된다. 문자를 몰래 자르지 않는다.
- 클라이언트 수정시각 + deviceId 충돌 규칙은 유지한다. 기기 시계 차이와 서버에서 밀린 수정은 복구본으로 확인할 수 있다. 서버 도착 순서만으로 오프라인 편집을 덮어쓰지 않는다.

## 보안과 업데이트

- 토큰을 보내기 전에 HTTPS, 정확한 script.google.com 호스트, `/exec` 배포 주소인지 검사한다. 요청 referrer도 보내지 않는다.
- 업무명·메모·회고·즐겨찾기 등 `=`로 시작하는 입력은 시트에서 수식이 되지 않도록 문자로 저장한다. CSV는 수식 시작 문자를 보호한다. CSV 보호용 탭은 다른 프로그램에서 원문 일부로 보일 수 있으므로 원본 보존/복원에는 JSON을 사용한다.
- 인증 실패 시 시트 식별값 등의 메타데이터를 보내지 않는다. 토큰은 JSON 백업과 복구자료에 포함하지 않는다.
- GET URL에 토큰과 payload가 포함되는 구조적 노출 가능성과 브라우저 localStorage의 평문 저장은 남는다. 보안 수준이 높은 회사 시스템의 대체 수단이라고 보장하지 않는다.
- 서비스 워커는 파일별 SHA-256 검증을 통과한 한 세트를 캐시한다. 다른 앱의 캐시를 지우지 않으며 작성 중인 창을 강제로 새로고침하지 않는다. 새 버전은 이전 창을 모두 닫은 다음 활성화된다. 설치된 이후 앱 셸은 같은 캐시에서 읽어 HTML과 JS가 섞이지 않게 한다.
- 검증값은 UTF-8 텍스트의 CRLF를 LF로 정규화해 계산했다. 직접 파일을 수정하면 sw.js의 RELEASE_HASHES도 갱신해야 한다. 변경된 배포 코드는 항상 sw.js CACHE_NAME과 앱 버전을 함께 올린다.

## 유지한 호환성

APP_ID는 `daeon-worklog`, API schemaVersion은 3이다. 기존 `worklog_logs`, `worklog_reflections`, `worklog_outbox`, 즐겨찾기 키와 시트 컬럼, 기록 ID를 유지한다. 예전 `dayeon-worklog` JSON 백업과 v8.7.0/8.7.1 일괄 작성본을 수용한다. 요청일시 직접 입력, 자동 시각 갱신, 개별 요청일시/예정일의 명시적인 공통값 복귀 동작을 유지했다.

새 서버는 `safeDeleteV1`, `literalTextV1`을 추가로 알린다. 새 앱은 이 기능이 없는 서버에 쓰기를 시작하지 않고 업데이트 안내를 표시한다. 이전 앱은 새 서버의 기존 API를 계속 읽을 수 있다.

## 파일과 검증

- index.html/style.css: 저장 상태, 삭제 취소, 수정 이어쓰기, 미래 요청 접기, 평가용 출력, 복구 화면.
- app.js: 저장 잠금, 전송/수신 오류 보존, 작성본과 복구 기능, 평가용 출력, URL·CSV 보호.
- Code.gs: 삭제 tombstone, 문자열 저장, 읽기 잠금, 부분 저장 재시도, 토큰/메타데이터 보호.
- sw.js: v8.8.0 캐시와 배포 파일 검증, 앱 범위 캐시 정리.
- manifest.json과 README_아이콘_안내.txt: 원본 그대로 포함.
- 검증 범위와 실기기 확인 사항은 `v8.8.0_검증_결과.md` 참고.
